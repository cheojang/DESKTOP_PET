# 외부 AI 플랫폼 활용 모션 제작 워크플로우 (학습 기록)

> 상태: **참고 지식만 저장.** 이 워크플로우는 여기서 직접 구현/실행하지 않는다.
> 사용자가 별도 AI 플랫폼(시댄스 2.0 등)에서 실제 제작을 맡길 예정이며,
> 이 문서는 그때 쓸 프롬프트 로직·구조를 재사용할 수 있게 기록해 둔 것이다.

## 관찰된 2단계 파이프라인

레퍼런스는 "상표명 → 로고 → 루핑 애니메이션"을 만드는 스레드였지만,
**구조 자체가 범용 캐릭터 모션 파이프라인**이라 데스크톱 펫에도 그대로 대입 가능하다.

### 1단계 — 정지 이미지 생성 (이미지 생성 플랫폼)
원문 프롬프트 요지(2/3):
> 입력한 [이름]만 보고 의미·어감·분위기를 분석해 가장 어울리는 [주체]를 스스로 선정.
> 귀엽고 단순한 손그림 느낌의 미니멀 라인아트. 흰 배경, 검은 윤곽선만.
> **옆면(side-view)**이 나오게. 몸은 둥글고 친근하게, 눈·입은 최소한의 선.
> 짧은 다리·작은 귀처럼 핵심 특징만 남겨 한눈에 알아볼 수 있게.
> 불필요한 장식·복잡한 음영·사실적 질감 제외. 실사용 가능한 깔끔한 심볼로.

**핵심 기법**: 이름/컨셉의 "의미"를 분석시켜 플랫폼이 스스로 형태·개체를 선택하게 위임하는
방식(제로샷 해석) + 스타일 제약(라인아트·미니멀·단순 특징)을 명시적으로 규정.

### 2단계 — 정지 이미지 → 루핑 영상 (시댄스 2.0, image-to-video)
원문 프롬프트 전문(3/3):
> 로고 의미에 맞게 [주체]가 [행동]하고 있는 애니메이션 만들어줘!
> **애니메이션은 끝과 시작 모션이 동일해서 애니메이션이 루핑되어야 함!**
> **카메라 이동 및 줌인·줌아웃 금지. [주체]만 움직임!**

**핵심 기법**: 3개 제약을 한 문장씩 명시적으로 못박음 —
① 루프 폐곡선(끝=시작) ② 카메라 고정(이동·줌 금지) ③ 모션 범위 한정(주체만).
이 3제약이 없으면 영상 생성 모델은 기본적으로 카메라 드리프트·줌·배경 변화를
자유롭게 넣어버리므로, **매번 명시적으로 배제**해야 한다.

## 데스크톱 펫에 대입할 프롬프트 템플릿 (초안 — 실제 플랫폼 투입은 사용자가 별도 진행)

### 1단계 템플릿 (캐릭터 정지 이미지 — 이미 `reference_baby.jpg`로 확보됨)
```
[캐릭터: 핑크 후드 우주복을 입은 치비 아기, 후드에 작은 귀 2개+물방울 도트,
크림색 안감, 흰 프릴 칼라, 앰버 단추 3개, 흰 발싸개]가 [상태]하고 있는 모습을
귀엽고 단순한 3D풍 캐릭터 아트로. 정면 또는 측면, 2등신 비율, 부드러운 셀 음영.
배경 투명 또는 단색. 불필요한 장식·복잡한 질감 제외.
```

### 2단계 템플릿 (상태별 루핑 모션 — 시댄스 등 image-to-video)
```
이 캐릭터가 [상태 행동: 예- 제자리에서 좌우로 뒤뚱뒤뚱 걷는 / 앉아서 꾸벅꾸벅 조는 /
위에서 잡혀 대롱대롱 흔들리는 / 놀라서 팔다리를 허우적대며 떨어지는] 애니메이션을 만들어줘!
애니메이션은 끝과 시작 모션이 동일해서 루핑되어야 함!
카메라 이동 및 줌인·줌아웃 금지. 캐릭터만 움직임! 배경 고정!
```

상태 매핑 (우리 상태머신 5종 → 행동 서술):
| 상태 | 행동 서술 초안 |
|---|---|
| IDLE | 제자리에 서서 숨쉬듯 아주 미세하게 위아래로 움직임 |
| WALK | 양옆으로 뒤뚱뒤뚱 걷기 (다리 교대, 팔 스윙) |
| SLEEP | 앉아서 꾸벅꾸벅 졸며 위아래로 숨쉬기 |
| DRAG | 머리 위에서 잡혀 대롱대롱 좌우로 흔들림 |
| FALL | 팔다리를 허우적대며 놀란 표정으로 떨어짐 |

## 산출물 형태 차이 — 주의(향후 통합 시 필요한 작업, 지금은 미착수)
- 시댄스 등은 **영상(mp4/webm)**을 출력. 우리 렌더러(`pet_renderer.py`)는 현재
  **투명 PNG 스프라이트 프레임**을 합성하는 구조.
- 영상 결과를 쓰려면 훗날: ① 프레임 추출(예: 루프 1사이클 구간을 N등분 PNG로 캡처)
  ② 배경 제거(원 배경이 흰색/단색이면 크로마키 또는 rembg) ③ `assets/pose_*.png`
  네이밍 계약에 맞춰 배치 — 하는 후처리 단계가 필요함. **이 문서는 그 결정을 내리지 않는다.**
- 얼굴 합성(`FACE_ANCHORS`) 계약과의 정합도 별도 검토 필요 — 영상 소스는 후드 개구부
  좌표를 코드가 알 수 없으므로, 프레임 추출 후 수동/보조 도구로 앵커를 다시 잡아야 함.

## 우리 쪽 기존 지식과의 연결
- 루프 3제약(끝=시작/카메라 고정/주체만 움직임)은 이미 `motion-doctrine.md`의
  원칙 1·2·4와 동일하다 — **매체(SVG 프레임 vs AI 영상)가 달라도 원칙은 같다.**
  두 문서는 서로 참조한다.
- `motion-doctrine.md`의 원칙 3(접지 안정)·5(의미 있는 모션)는 AI 영상 프롬프트에도
  그대로 요구사항으로 넣을 것: "발이 미끄러지지 않게", "행동이 상태를 명확히 드러내게".
